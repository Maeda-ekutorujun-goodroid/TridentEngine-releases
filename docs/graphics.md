# グラフィックス

3Dモデル、ライティング、Skybox / Fog / Bloom、Litマテリアル、Particle、LODと描画カリング。

[← ドキュメント一覧へ戻る](index.md)

## まず見栄えを上げる3ステップ

難しい設定を覚える前に、この3つだけで画面の印象が大きく変わります。

1. **影をつける** — Hierarchyの「太陽光」（平行光源）を選び、Inspectorで
   影を有効にします。品質プリセットがLowだと影は無効なので、
   プロジェクト設定でMedium以上にします。
2. **空・霧・発光** — Inspectorの「シーン環境」でSkybox、Fog、Bloomを
   ONにします。外部テクスチャなしで空と遠景のなじみ、光のにじみが出ます。
3. **材質感** — MeshRendererのマテリアルで「粗さ」を下げると金属や
   プラスチックのような光沢に、上げるとマットな質感になります。
   `.dds`キューブマップをSkyboxへ設定すると、粗さに応じた正確な
   映り込み（IBL）になります。

## 3Dモデル

Asset BrowserとModelRendererは次のDirectXTK形式に対応しています。

- `.cmo`
- `.sdkmesh`
- `.vbo`
- `.gltf`
- `.glb`
- `.fbx`

FBXは中間形式へ変換せず、元の`.fbx`からメッシュ、マテリアル、スキン、
アニメーションを直接読み込んで描画します。

GameObjectへModelRendererを追加し、Asset Browserでモデルを右クリックして
「モデルを割り当て」を選ぶか、Inspectorへドラッグ＆ドロップします。

### FBXの静的パーツ自動結合

アニメーションを持たないFBXでは、インポート時にボーン（スキン）の付いていない
パーツを同じマテリアルどうしで1つの頂点／インデックスバッファへ自動結合します。
DCCツールから、ボディパネル・ボルト・トリムなどが数百個の別パーツのまま書き出されて
いると、パーツ単位のドローコールと状態変更がCPU負荷の支配要因になるためです。

結合結果はConsoleの`FBX imported:`ログに`parts=717->15 (merged)`の形で出ます。
結合してもなおドローコールが64を超えるモデルには、DCCツール側でメッシュを
まとめてから書き出すことを勧める警告を出します。スキン付き、またはアニメーションを
含むモデルは結合対象外で、従来どおりの描画経路を使います。

FBX側の単位設定が実寸と食い違っている場合は、Asset Browserで`.fbx`を選び、
Inspectorの「インポートスケール」で補正できます
（[エディター](editor.md)の「Model Asset Inspector」を参照）。

### モデルのマテリアル取り込み

glTF／FBXからは、モデルが持っている次のマテリアル情報を読み込みます。
読み込んだモデルは既定でTrident Lit（Cook-Torrance GGXのPBR）で描かれるため、
マテリアル上書きを有効にしなくても法線マップとmetallicが効きます。

| 項目 | glTF | FBX |
| --- | --- | --- |
| ベースカラー | `baseColorFactor` | `base_color` |
| アルベドテクスチャ | `baseColorTexture` | `base_color`のテクスチャ |
| 法線マップ | `normalTexture` | `pbr.normal_map` |
| 粗さ | `roughnessFactor` | `pbr.roughness` |
| metallic | `metallicFactor` | `pbr.metalness` |
| 粗さマップ | `metallicRoughnessTexture`の`G` | `pbr.roughness`のテクスチャ |
| metallicマップ | `metallicRoughnessTexture`の`B` | `pbr.metalness`のテクスチャ |
| 遮蔽（AO）マップ | `occlusionTexture`の`R`（`strength`込み） | `pbr.ambient_occlusion`のテクスチャ |
| 発光色 | `emissiveFactor`（`KHR_materials_emissive_strength`込み） | `pbr.emission_color`×`pbr.emission_factor` |
| 発光マップ | `emissiveTexture` | `pbr.emission_color`のテクスチャ |
| 不透明度 | `alphaMode` | `pbr.opacity` |

粗さ・metallicマップは係数へ掛け算されます（glTF仕様と同じ扱い）。
glTFでは`metallicRoughnessTexture`の1枚にG＝粗さ、B＝metallicが入っており、
FBXでは別画像ですが、どちらもグレースケールなら同じ読み方で一致します。

**遮蔽マップは環境光／IBLにだけ掛かります。** 直接光にも掛けると、影の中が
二重に暗くなって汚れて見えるためです（glTF仕様も同じ扱いです）。

発光（emissive）はライティングと無関係に加算されるので、**影の中でも暗い
シーンでも光ります。** 看板・ネオン・モニター・魔法エフェクトなどに使えます。
発光を1より強くすると（glTFの`KHR_materials_emissive_strength`、または
発光色を大きくする）Bloomがそのまま滲みを付けるので、光っている感じが
出ます。Bloomは「シーン環境 → Bloom」で有効にしてください。Fogは発光の
あとに掛かるため、遠くのネオンは霧に沈みます。

Inspectorの「マテリアルを上書き」を有効にすると、モデル自身の材質の代わりに
ModelRendererのLitMaterialが使われます。上書き中はアルベドと法線マップも
LitMaterial側の設定が優先されます。

#### ポリゴンの面が見えるようになった場合

Trident Litは**ピクセル単位**でライティングを計算します。従来のDirectXTK
描画は頂点単位（Gouraud）で、頂点で求めた明るさを面の中で補間していたため、
面ごとの陰影差が塗りつぶされて滑らかに見えていました。

そのため、**分割の粗いモデルは面の境目が見えるようになります。**
これは計算が正確になった結果で、不具合ではありません。滑らかに見せたい
場合は次のどちらかで対応してください。

- DCCツール側で法線を平滑化（スムーズシェーディング）して書き出し直す。
  面ごとに法線が分かれていると、ピクセル単位では段差として出ます
- そのモデルだけ下の「従来のDirectXTK描画を使う」をオンにする

#### 従来のDirectXTK描画へ戻す

Inspectorの「従来のDirectXTK描画を使う」をオンにすると、そのModelRendererだけ
以前の描画（DirectXTK `SkinnedEffect`のBlinn-Phong）に戻ります。法線マップと
metallicは効かなくなります。旧バージョンと同じ見た目を保ちたいモデルにだけ
使ってください。現在どちらで描かれているかはInspectorの「描画経路」に出ます。

シーンJSONの`useLegacyShading`が未指定のときはTrident Litとして読み込むため、
既存シーンをそのまま開くだけで新しい描画に切り替わります。

## ライティング方針

Scene共通の環境光とDirectional／Point／Spot Lightコンポーネントを実装済みです。

- Inspectorの「シーン環境」で環境光カラーと強度を編集
- GameObjectへ「平行光源」「ポイントライト」「スポットライト」を追加
- Transformの回転から照射方向を計算
- ライト色、強度、範囲、スポット内側／外側角度をInspectorで編集
- ポイント／スポットはクラスタライトカリング（Forward+）で最大256灯
  （下の「ライト数の考え方」を参照）
- ライト設定と環境光を`.scene.json`へ保存
- Scene Viewに方向矢印、範囲球、スポットコーンのギズモを表示
- Directional Lightごとの影、描画距離、濃さ、深度／法線バイアス設定
- 1～4分割のカスケードシャドウと分割バランス設定

新規シーンにはメインカメラと「太陽光」が自動作成されます。既存シーンにも
GameObjectの「コンポーネントを追加」から各ライトを追加できます。環境光は3D描画だけへ
適用され、SpriteRenderer／TextRendererなどの2D描画には影響しません。

MeshRendererは`assets/shaders/TridentLit.hlsl`を使い、ピクセル単位のLambert＋Blinn
ライティング、距離の二次減衰、スポットコーン減衰を計算します。マテリアル上書きを
有効にした互換性のある静的ModelRendererも同じシェーダーを使うため、Point／Spot Lightを
ピクセル単位で計算します。DirectXTKへフォールバックしたモデルでは、各モデル中心で
最も強い方向のライトへ近似します。近似に使える灯数はエフェクトの種類で決まり、
DGSLEffect（CMOのカスタムマテリアルなど）は4灯、BasicEffectやSkinnedEffectなど
それ以外のDirectXTKエフェクトは3灯までです（DirectXTKの仕様上の上限）。

影を有効にした最初のDirectional Lightは、カメラの視錐台を最大4範囲へ分割し、
各範囲を2048×2048のTexture2DArrayへ毎フレーム描画します。近景ほど狭い範囲へ
解像度を集中できるため、単一ShadowMapより遠距離と精細さを両立できます。
Inspectorではカスケード数と、均等分割／近景重視を調整する分割バランスを設定できます。

各正投影範囲はShadowMapのテクセル単位へスナップされ、カメラを少し動かしたときの
影の揺れを抑えます。Litシェーダーではカメラ深度からカスケードを選び、
境界付近10%を次のカスケードとブレンドして切り替え線を抑えます。
影の輪郭は3×3のPCF（比較サンプラーの2×2と合わせて実質4×4相当）で
柔らかくなり、スポット影も3×3、ポイント影は接平面5タップのPCFです。
深度バイアス／法線バイアスでシャドウアクネと浮きを調整できます。
MeshRendererとModelRendererは影を落とします。共通Litシェーダーで描画される
MeshRendererと静的ModelRendererは影を受けます。

### ライト数の考え方（Forward+）

標準のLitシェーダー（MeshRenderer／ModelRenderer）は**クラスタライト
カリング**で描画します。視錐台を16×9×24の格子（クラスタ）に切り、
Compute Shaderが「そのクラスタに届くライトの番号表」を毎フレーム作るので、
ピクセルごとの計算量は「近くにあるライトの数」で決まります。シーン全体では
**ポイント＋スポット合計256灯**まで置けます。

- 品質設定のポイント／スポット上限（High=12/4など）は、**従来の16灯経路**
  （下記）にだけ効きます。Litシェーダーのオブジェクトには影響しません
- 1クラスタに同時に届くライトは32灯まで。狭い場所に33灯以上重ねると
  超えた分は落ちます（暗くなるだけで破綻はしません）
- 正射影（2Dモード）のカメラでは自動的に従来経路へ切り替わります

**従来の16灯経路が残る場所**: 自作Shader（`TRIDENT_PROPERTIES`で作った
カスタムマテリアル）とDirectXTKフォールバックのモデルは、従来どおり
「シーン全体から先着N灯」の定数バッファを読みます。自作Shaderの
オブジェクトが多灯シーンで暗くなる場合はこれが原因です。

2D描画は基本的に非ライティングのまま維持し、必要になった段階で2D Lightを別系統として
追加します。

## Skybox、Fog、Bloom

Inspectorの「シーン環境」から、シーン全体の空・霧・発光表現を設定できます。

- Skybox：上空、地平線、下側の3色と明るさを持つプロシージャル空
- Fog：色、開始距離、終了距離、密度を指定する距離フォグ
- Bloom：しきい値、強度、広がりを指定する全画面ポストエフェクト

Skyboxはカメラの向きから背景を生成するため、外部テクスチャなしで利用できます。
`.dds`キューブマップを指定するとIBL（環境反射・環境拡散）が有効になり、
初回に一度だけGPUでGGX事前畳み込み（粗さ別ミップのスペキュラキューブ）と
コサイン畳み込みの放射照度キューブを生成します。これにより、粗いマテリアルは
ぼけた映り込み、滑らかなマテリアルは鮮明な映り込みと、粗さに正確な環境反射に
なります（BRDF項はLUT不要の解析近似で評価）。
FogはTridentLitシェーダーに加え、DirectXTK標準Effectへフォールバックしたモデルにも
適用されます。BloomはScene View、Game View、エディターなしの通常ゲーム描画に対応し、
明るいライトや加算パーティクルの周囲へ柔らかな発光を加えます。

設定はシーンJSONの`environment.sky`、`environment.fog`、`environment.bloom`へ保存されます。
サンプルシーンでは3機能が有効になっており、Inspectorのチェックボックスで個別に比較できます。

## Litマテリアル

MeshRendererとModelRendererは共通の`LitMaterial`を持ち、Inspectorから次を編集できます。

- ベースカラーとアルファ
- 粗さ
- metallic
- アルベドテクスチャ
- 法線マップ
- 法線強度
- 粗さマップ／metallicマップ（数値へ掛け算されます）
- 遮蔽（AO）マップと遮蔽の強さ（環境光／IBLにだけ掛かります）
- 発光マップと発光色（ライティングと無関係に加算。Bloomが滲ませます）

PBRマップと発光はInspectorの「PBRマップ（粗さ・金属度・遮蔽・発光）」を
開くと編集できます。各枠へ画像をドラッグ＆ドロップするか、Asset Browserで
画像を選んで「選択画像を割り当て」を押します。読み込みモデルが自分で
持っているマップは自動で使われるので、こちらで指定する必要があるのは
手置きのMeshRendererか、モデルのマップを差し替えたいときだけです。

Asset Browserで画像を右クリックし「画像を割り当て」を選ぶと、選択中のMeshRendererでは
アルベドへ、ModelRendererではマテリアル上書きを有効にしてアルベドへ割り当てられます。
Inspectorのアルベド欄／法線マップ欄へ画像を
ドラッグ＆ドロップするか、「選択画像をアルベドへ」「選択画像を法線へ」も使用できます。

マテリアル設定とテクスチャパスはシーンJSONへ保存されます。画像ファイルやフォルダーの
移動・改名では参照が自動更新され、削除時にはSpriteRenderer／ModelRendererと同様に
参照元として警告されます。

Asset Browserのフォルダーまたは空白の右クリックメニューから`.material.json`を
作成できます。MeshRenderer／ModelRendererへドラッグするか、Materialの右クリック
メニューから「Materialを割り当て」で共有Materialを設定します。Inspectorでは次の操作が可能です。

MaterialをAsset Browserで単クリックすると専用Inspectorが開き、ベースカラー、粗さ、
アルベド、法線マップ、Shader、カスタムパラメーターをまとめて編集できます。
「選択オブジェクトへ適用」で、選択中のMeshRenderer／ModelRendererへ直接割り当てられます。
ShaderはMaterial Inspectorおよび各Rendererの候補一覧から選択でき、標準Litへも戻せます。

- 「Materialへ保存」で現在の値を共有ファイルへ保存
- 「再読込」でディスク上の共有値へ戻す
- 「個別化」で現在値を保ったまま共有参照を解除

共有Materialを保存すると、同じシーン内でそのMaterialを参照する全Rendererへ
即座に反映されます。シーンJSONには共有Materialのパスとフォールバック用の現在値が
保存されるため、既存シーンとの互換性も維持されます。

`TridentLit.hlsl`はGeometricPrimitiveのUVを使ってアルベドをサンプリングします。
法線マップ用の接線空間はピクセルシェーダー内の位置／UV微分から生成するため、
プリミティブ頂点へ接線データを追加する必要はありません。法線マップ未設定時は
内部のフラット法線テクスチャを使用します。

### カスタムShader

書き方の解説とサンプルHLSLは[カスタムShaderガイド](shaders.md)に
まとまっています（2Dスプライト用・画面全体ポストエフェクトもこちら）。

Asset Browserのフォルダー内で右クリックし「新規カスタムShader」を選ぶと、
編集可能なHLSL雛形を作成できます。HLSLをダブルクリックしてコードエディターで編集し、
Mesh Renderer／Model RendererのInspectorへドラッグしてMaterialに設定します。
保存したHLSLは実行中も自動再コンパイルされ、失敗時はInspectorへエラーを表示しながら
直前の正常なShader（未成功なら標準Lit）で描画を継続します。

カスタムShaderはShader Model 5.0の`VSMain`と`PSMain`を持ち、雛形と同じ
`ObjectBuffer`レイアウトを使用します。Inspectorの「カスタムShaderパラメーター」から
`CustomParameters[0]`〜`CustomParameters[3]`へ4本の`float4`を渡せます。
Shaderパスと値は`.material.json`（version 2）およびシーンへ保存されます。
静的モデルは位置・法線・UVが共通Lit形式と互換な場合に対応します。
スキニング（ボーン）モデルも、Shaderに`VSSkinnedMain`があればカスタム
Shaderで描画します（エンジンがスキニング用に別途コンパイルし、専用の
入力レイアウトを作ります）。

DirectXTK形式のModelRendererは、上書きが無効ならモデル内蔵マテリアルをそのまま使用します。
上書きを有効にした静的モデルが位置・法線・UVを持つ場合はTrident Litへ自動的に切り替わり、
ベースカラー、粗さ、アルベド、法線マップ、Point／Spot Light、Directional Shadowが
MeshRendererと同じ方法で適用されます。Inspectorの「描画経路」で実際の経路を確認できます。

`VSSkinnedMain`を持たないShaderを指定したスキニングモデルや、法線／UVのない
モデルはDirectXTK内蔵Effectへ安全にフォールバックします。
その場合も対応可能な色・粗さ・テクスチャ設定を内蔵Effectへ変換して適用します。
各ModelRendererは独立したEffectを生成するため、同じモデルを複数配置しても設定は漏れません。

## 3D Particle System

GameObjectへ`パーティクルシステム`を追加すると、カメラを向く3Dビルボード粒子を
Scene ViewとGame Viewへ描画できます。Inspectorでは次を編集できます。

- 最大数、毎秒の生成数、寿命、初速、開始サイズ
- 寿命に沿ったサイズ倍率と開始／終了RGBAカラー
- 重力、再生時間、ループ、自動再生、エディターでのリアルタイムプレビュー
- Cone、Sphere、BoxのEmitter形状
- 加算合成／通常アルファ合成と任意のPNGテクスチャ

再生、停止、再開始、32個のBurstをInspectorから試せます。通常アルファ合成では
カメラから遠い順に粒子を描画し、加算合成では発光エフェクト向けの高速な描画を行います。
Scene／Prefab保存、GameObject複製、アセットの名前変更・移動・削除時の参照追従にも対応します。
サンプルSceneの`発光パーティクルサンプル`には、透過済みの
`textures/particle-glow.png`を使った青いエネルギー噴出を配置しています。

## ビルボード（画像をカメラへ向ける）

3D空間に置いた画像を常にカメラへ向けたいときは、`ビルボード`コンポーネント
（コンポーネントを追加 → Animation）を付けます。木・草、頭上のHPバー、
光の玉、アイテムのアイコンなどがこれです。

画像はMesh RendererのPlaneにテクスチャを貼って作ります。

```cpp
auto& iconObject = scene.CreateGameObject("Icon");
iconObject.AddComponent<Trident::MeshRendererComponent>(
    Trident::PrimitiveShape::Plane,
    DirectX::XMFLOAT4{ 1.0f, 1.0f, 1.0f, 1.0f },
    "textures/icon.png");
iconObject.AddComponent<Trident::BillboardComponent>();
```

ビルボードには大きく**2種類**あり、違いが出るのは画面の端です。

| | 向き方 | 端での見え方 |
|---|---|---|
| **カメラの位置を向く** | 板ごとにカメラの座標へ向く | 端の板がこちらへ振り向くように回って見える |
| **画面と平行にする** | カメラの向きに合わせる（全部同じ向き） | どこにあっても同じ向き・同じ形。歪まない |

板状の絵は**画面と平行**（既定）が自然です。球状の光のように「本当に立体
である」ものは**位置を向く**方が正しく見えます。

**3D空間にUIを出すときは必ず画面と平行**にしてください。頭上の名前、
ダメージ表示、「調べる」のプロンプトなどは文字が読めることが最優先です。
位置を向く方式だと画面の端で板が振り向くため、文字が斜めに歪んで読み
にくくなります。

- **向け方**（それぞれに「立ったまま」版があります）
  - `ScreenAligned`（既定）— 画面と平行。全部が同じ向きになります
  - `FaceCameraPosition` — カメラの座標を向きます
  - `UprightScreenAligned` — 立ったまま、画面の向きに合わせます。並べた
    草がすべて同じ向きになるので列が揃って見えます
  - `UprightFaceCameraPosition` — 立ったまま、カメラの座標を向きます。
    1本の木・頭上のHPバーはこちらです
  - `LookAtPosition` — カメラではなく指定したワールド座標を向きます
- **向ける面** — Mesh RendererのPlaneは面が真上（+Y）を向いているので、
  画像を貼る用途では既定の`Up`のままで構いません。正面が+Zのモデルを
  向けたいときは`Forward`にします
- 回転だけを毎フレーム上書きします（位置と大きさは触りません）。書くのは
  全コンポーネントのUpdateが終わった後（LateUpdate）なので、カメラを
  スクリプトで動かしていても1フレーム遅れません
- 親がいても大丈夫です。親の回転を打ち消したローカル回転を入れるので、
  親ごと回してもカメラを向いたままになります
- 向くのは**メインカメラ**で、**再生中だけ**です。エディターのシーンビューは
  自分のカメラで見ているため、止めているあいだは付けた向きのまま編集できます

パーティクルの粒はこのコンポーネントを付けなくても常にカメラを向きます
（[3D Particle System](#3d-particle-system)のBillboardモード）。

## LODと描画カリング

遠距離用の軽量モデルは、それぞれ別の子GameObjectへModelRendererまたは
MeshRendererとして配置し、親へ`LOD Group`を追加します。InspectorでLODごとの
最大距離と表示対象GameObject、完全に非表示にする距離を設定できます。

```cpp
auto& group = scene.CreateGameObject("Building LOD");
auto& high = scene.CreateGameObject("Building High");
auto& low = scene.CreateGameObject("Building Low");
high.SetParent(&group);
low.SetParent(&group);

group.AddComponent<Trident::LODGroupComponent>(
    std::vector<Trident::LODLevel>{
        { 25.0f, high.Id() },
        { 80.0f, low.Id() }
    },
    160.0f);
```

3D描画では次の順番で表示対象を絞り込みます。

1. カメラ距離からLODを1つ選択
2. Frustum Cullingでカメラの視錐台外を除外
3. 32×18の保守的な深度グリッドで、手前の不透明モデルに完全に隠れた物体を除外

OcclusionはGPU Query待ちを発生させない軽量なCPU方式です。Box／Capsule／Sphere Colliderが
ある場合はそのBoundsを使い、それ以外はTransformされた単位Boundsを使います。
正確なカリング範囲が必要な大型モデルにはColliderを追加してください。ワイヤーフレーム
ModelRendererは遮蔽物として扱いません。

Inspectorの「シーン環境 → 描画カリング」で各機能のON/OFFと、総Renderer数、
表示数、LOD／視錐台／遮蔽で除外された数を確認できます。設定はSceneへ保存されます。

オブジェクト単位の例外は「描画カリング」コンポーネントで指定します
（「コンポーネントを追加 → Rendering → 描画カリング」）。

- **カメラ外でも描画** — 視錐台・遮蔽カリングの対象から外し、常に描画します。
  広い地形や背景向けです
- **カリング余白** — 視錐台カリングの境界をワールド単位で広げます。頂点
  シェーダーで揺らす草木など、Boundsより大きく見えるものの消え際を防ぎます

コンポーネントが付いていないオブジェクトは通常どおりカリングされます。以前は
全GameObjectのInspectorへ常時この2項目が表示されていましたが、カメラやライトには
意味がないためコンポーネントへ分離しました。古いシーンの設定は読み込み時に
自動でコンポーネントへ変換されます。

## リフレクションプローブ（ローカルの環境反射）

SkyboxのIBLはシーン全体で1つなので、屋内の金属が屋外の空を映してしまいます。
「リフレクションプローブ」コンポーネント（コンポーネントを追加 → Rendering）を
置くと、その位置から見たシーンをキューブマップへ焼き、**中心がプローブの
影響範囲に入っているオブジェクト**の反射と環境光がそれに置き換わります。

- **影響範囲** — 半径（ワールド単位）
- **強さ** — SkyのIBL強度と同じ扱いです
- **混ぜ始める距離** — 隣のプローブと混ぜ始める厚み。0のままだと境界で
  切り替わります（詳しくは下の「プローブのブレンド」）

ベイクはシーン読み込み後に自動で1回走ります。物を動かしたらInspectorの
「ベイクし直す」を押してください。結果はGPUメモリー上だけに保持され、
ファイルへは保存されません（シーンを開き直すと焼き直されます）。

- 焼くのはポスト処理前のHDRリニアの絵です（IBLとして正しい値）
- 金属・低粗さのマテリアルほど効果がはっきり出ます。鏡面の球を
  プローブの中心に置くと、周囲がそのまま映り込みます
- ベイク中はプローブ自身の結果を使いません（プローブがプローブを
  映す循環を防ぐため）

### プローブのブレンド（境界で映り込みが飛ぶのを防ぐ）

プローブが1個だけのときは、範囲に入っているものがそのまま使われます。
複数が重なっている場所では**影響が一番大きいものと2番目**を混ぜます。

混ぜる比率は「混ぜ始める距離」から決まります。0のままだと混ぜず、境界を
またいだ瞬間に映り込みが切り替わります（部屋を移動すると鏡面がパッと
変わって目立ちます）。値を入れると、範囲の縁からその厚みのあいだで
少しずつ隣へ移ります。

```cpp
// 隣の部屋のプローブと3mかけて混ぜる
probe.SetBlendDistance(3.0f);
```

- 混ぜるのは**2個まで**です。3個以上が重なっている場所では、影響の
  大きい2つが選ばれます
- 反射の向きはプローブごとに**自分の箱**で補正します。別の形の部屋を
  またぐときも、それぞれの壁が正しい距離で映ります
- 強さも比率で混ざるので、明るさの違うプローブをまたいでも飛びません
- **すべてのプローブが0のままなら、絵は1バイトも変わりません。**
  既存のシーンに影響を出さないため、既定値は0にしています

### ボックス射影（部屋の形に合わせる）

キューブマップは本来「無限に遠い景色」として引かれるので、そのままだと
床や壁がカメラの動きについてこず、狭い部屋の中では反射が滑って見えます。

Inspectorの「箱の大きさ（半径）」に部屋の半径（中心からの距離。
XYZそれぞれ）を入れると、反射の向きをその箱との交点へ補正します。
壁が正しい距離に映るので、鏡面の床に部屋がぴたりと収まります。

```cpp
auto& probe = roomObject.AddComponent<Trident::ReflectionProbeComponent>(
    20.0f,   // 影響範囲
    1.0f);   // 強さ
// 10m × 6m × 8m の部屋なら、半径は 5 / 3 / 4。
probe.SetBoxExtents({ 5.0f, 3.0f, 4.0f });
```

- **3軸すべてに正の値**を入れたときだけ有効になります。0を含んでいると
  従来どおり無限遠として扱います（既存のシーンの見た目は変わりません）
- 箱の中心はプローブの位置です。部屋の中心にプローブを置いてください
- 屋外や広い空間では不要です。無限遠のままのほうが自然に見えます

## SSAO（遮蔽による陰り）

物が接している隙間や角を暗くして、接地感を出します。Inspectorの
「シーン環境 → SSAO（遮蔽による陰り）」で有効化し、陰りを探す距離と
濃さを調整します。

```cpp
auto occlusion = scene.AmbientOcclusion();
occlusion.enabled = true;
occlusion.radius = 0.5f;    // 陰りを探す距離（ワールド単位）
occlusion.strength = 0.6f;  // 濃さ（0～1）
scene.SetAmbientOcclusionSettings(occlusion);
```

- **深度バッファだけ**から計算します。法線バッファを持たない前方
  レンダリングでも動くよう、法線は上下左右の深度から再構成しています
  （追加のGバッファは作りません）。軸ごとに段差の小さい側を選ぶので、
  曲面でも輪郭沿いでも破綻しません。
- **半解像度で計算し、深度を見るブラーをかけます。** AOは低周波なので
  半分の解像度で足りて、計算量は1/4になります。ブラーが深度の段差を
  越えないため、手前の物の縁へ陰りが漏れることもありません。
- **環境光／IBL項だけを暗くします。** ライティングより前に深度だけの
  プリパスを走らせて遮蔽を用意し、Litシェーダーが環境光の項に対して
  掛けます。直接光や影の中は暗くならないので、影と陰りが重なって
  「汚れ」に見えることがありません。
  - 環境光の強度が0のシーンではSSAOの効果もゼロになります（掛ける先が
    無いため）。暗いシーンで効かないと感じたら、環境光かIBLの強度を
    上げてください。
  - プリパスはSSAOが有効なときだけ走ります。使わない構成では
    ジオメトリを2回描くコストがかかりません。
- 探索回数は品質プリセットで変わります（Low=8／Medium=12／High=16／
  Ultra=24）。多いほど滑らかですが重くなります。Customでは
  プロジェクト設定から個別に指定できます。
- 品質設定の「SSAO（遮蔽による陰り）」でも有効である必要があります
  （Bloomと同じ扱い。プリセットではHigh以上でオン）。Low／Mediumでは
  シーン側で有効にしていても描画しません。
- 自作Shaderのオブジェクトは、Shader側でSSAOを読む必要があります
  （[Shader](shaders.md)の「SSAOを受け取る」を参照）。読んでいない
  自作Shaderには陰りがかかりません。`TridentLit.hlsl`をそのまま使う
  MeshRenderer／ModelRendererは何もしなくてもかかります。
- 半径は小さめ（0.3～0.8m程度）が輪郭のはっきりした陰りになります。
  大きくするとぼんやり広がります。
- 距離が離れるほど画面上の探索範囲が小さくなるため、遠景の負荷は
  自然に下がります。

## TAA（時間的アンチエイリアス）

輪郭のギザギザを消します。Inspectorの「シーン環境 →
TAA（時間的アンチエイリアス）」で有効にします。

```cpp
auto temporal = scene.TemporalAntiAliasing();
temporal.enabled = true;
temporal.historyWeight = 0.9f;    // 前フレームを残す比率
temporal.jitterScale = 1.0f;      // ずらす量（ピクセル）
temporal.clampTolerance = 1.0f;   // 履歴を許す幅
scene.SetTemporalAntiAliasingSettings(temporal);
```

毎フレーム射影を**サブピクセルだけずらして**描き、前フレームの結果と
混ぜます。1枚のなかで平均を取るMSAAと違って時間をかけて平均するので
安く、輪郭だけでなくテクスチャのちらつきにも効きます。ずらし方はHalton列
（基数2と3）で、8枚で1周します。乱数だと同じ場所に固まる回があり、その
フレームだけ効かずにちらついて見えるためです。

- **前フレームをどこから読むか**は、深度からワールド座標を戻して前
  フレームの行列で射影し直して求めます（再投影）。カメラが動いても
  同じ場所を見続けられます
- **物体ごとの速度は持っていません。** そのため速く動く物の上では再投影が
  外れます。今のフレームの近傍9マスから色の範囲を作り、履歴をその範囲へ
  押し込むことで（近傍クランプ）残像を抑えています。**履歴を許す幅**を
  下げるとにじみが減り、上げるとギザギザ取りが強くなります
- **前フレームを残す比率**を上げるほど滑らかになりますが、動きに対して
  眠くなります。0.9前後が目安です
- **FXAAと二重にかけないでください。** どちらも輪郭を平すので、両方
  有効だと輪郭がぼやけます。TAAを使うならグラフィック品質のFXAAは
  切ってください
- ポスト処理の**一番先**にかけます。Bloomの後で混ぜると、前フレームの
  Bloomがさらに滲んで輪郭が二重になります
- リフレクションプローブのベイク中はずらしません（キューブに揺れが
  焼き付くため）
- 履歴と前フレームの行列は**ビューごと**に持ちます。エディターは
  シーンビューとゲームビューを同じフレームで描くため、共有すると
  互いを踏み合って再投影が壊れます
- SSRが読む「前フレームのカラー」はTAAで混ぜる**前**の絵です。混ぜた後を
  読ませると、TAAの履歴が反射経由でさらに積算されて像が流れます

## SSR（画面空間反射）

濡れた床、磨いた金属、水面に周りの景色を映します。Inspectorの
「シーン環境 → SSR（画面空間反射）」で有効にします。

```cpp
auto reflection = scene.ScreenSpaceReflection();
reflection.enabled = true;
reflection.intensity = 1.0f;         // 反射の強さ
reflection.maximumDistance = 12.0f;  // 映る距離（ワールド単位）
reflection.stepCount = 24;           // レイのサンプル数
reflection.thickness = 0.4f;         // 物の厚みの見積もり
reflection.roughnessCutoff = 0.45f;  // これより粗い面には掛けない
scene.SetScreenSpaceReflectionSettings(reflection);
```

**映るのは画面に写っているものだけです。** 画面の外にあるもの、物の裏側、
カメラの後ろは情報が無いので映せません。足りない分は
[リフレクションプローブ](#リフレクションプローブローカルの環境反射)や
SkyのIBLへ**滑らかに戻します**（急に切れると反射が四角く切り取られて
見えるため、画面の縁へ近いほど弱めています）。つまりSSRは環境反射を
置き換えるものではなく、**近くのものだけ精度を上げる足し算**です。

- **粗さ**が`roughnessCutoff`より小さい面にだけ掛かります。ざらざらした面の
  反射はぼやけていて、1本のレイでは表せないためです。鏡のような床を
  作りたいときは、マテリアルの粗さを0.05程度まで下げてください
- **物の厚み**は当たり判定の許容幅です。小さすぎるとレイが物をすり抜けて
  映らなくなり、大きすぎると物の裏側にも映り込みます
- 計算はLitシェーダーの中で行います。シェーダーが持っている**正確な法線**
  （ノーマルマップ適用済み）をそのまま使えるので、法線バッファを別に
  持つ必要がありません
- 色は**前フレームのHDR**を読みます。今描いている絵は完成していないため
  読めないからです。当たった点は前フレームの画面座標へ**再投影**するので、
  カメラが動いても映り込みの位置はずれません
- 深度はプリパスの結果を**コピーしたもの**を読みます。Litパス中は深度が
  書き込み先として刺さっているため、同じリソースをシェーダーから読むことは
  できません（D3D11の制約）。有効なときだけコピーが走ります
- 有効にした直後の1枚は前フレームが無いので映りません（2枚目から効きます）
- SSAOと同じく、自作Shaderのオブジェクトは自分で読む必要があります
  （`TridentLit.hlsl`の`EvaluateScreenSpaceReflection`が実装です）

## ボリュメトリックライト（光の筋）

空気中の塵に光が散る様子を描きます。窓から差し込む光、木漏れ日、霧の中の
逆光がこれです。Inspectorの「シーン環境 → 光の筋（ボリュメトリック）」で
有効にします。

```cpp
auto volumetric = scene.VolumetricLight();
volumetric.enabled = true;
volumetric.intensity = 0.35f;        // 筋の濃さ
volumetric.sampleCount = 32;         // レイのサンプル数
volumetric.maximumDistance = 24.0f;  // 届く距離（ワールド単位）
volumetric.scattering = 0.6f;        // 前方散乱（0～0.95）
scene.SetVolumetricLightSettings(volumetric);
```

- **影を有効にした平行光源（Directional Light）が必要です。** カメラから
  伸ばしたレイに沿って既存のカスケードシャドウを引き、「光が届いている
  区間」だけを積み上げます。影が無いと遮る物が分からないため、筋も
  出ません（品質設定で影を切っている場合も同じです）
- **筋の濃さ**は平行光源の強度に掛かります。太陽を明るくすれば筋も
  明るくなるので、この値は「空気の濃さ」として考えてください
- **前方散乱**を上げると、太陽の方を向いたときだけ強く光ります。0にすると
  全方向へ均一に散って「霧」に近い見た目になります
- **届く距離**は平行光源の「影の距離」（既定24m）までに抑えられます。
  影のカスケードが覆っていない範囲は遮る物が分からず、そのまま光として
  積まれて画面が白く霞むためです。もっと遠くまで筋を伸ばしたいときは、
  Directional Lightの影の距離を先に伸ばしてください
- **サンプル数**が少ないと縞（バンディング）が出ます。ピクセルごとに
  開始位置をずらしているので32程度でも実用になりますが、遅い環境では
  16まで落として距離を短くするほうが破綻しません
- ポスト処理の中では**Bloomより前・HDRのうち**にかけます。明るい筋が
  そのままBloomで滲み、トーンマップも通るため、後段でLDRへ足すより
  自然に馴染みます
- リフレクションプローブのベイク中はかけません（キューブマップに
  光の筋が焼き付くのを防ぐため）

## レンダーテクスチャ（ミニマップ・防犯カメラ）

Cameraの描画先を画面ではなくテクスチャにできます。Inspectorの
Camera→「描画先（Render Texture）」に名前を入れ、同じ名前を
Sprite RendererまたはUI Imageの「Render Texture」に指定すると、
そのカメラの映像が画面に出ます。ミニマップ、防犯カメラ、装備プレビュー、
ポータルはこれ1つで作れます。

```cpp
// 真上から見下ろすミニマップ用カメラ
auto& minimapObject = scene.CreateGameObject("Minimap Camera");
minimapObject.GetTransform().position = { 0.0f, 40.0f, 0.0f };
minimapObject.GetTransform().SetEulerAngles(
    { 1.5f, 0.0f, 0.0f });

auto& minimapCamera = minimapObject.AddComponent<Trident::CameraComponent>();
minimapCamera.SetTargetTexture("minimap");        // 描画先の名前
minimapCamera.SetTargetTextureSize(256, 256);     // 既定は512x512
minimapCamera.SetTargetClearColor({ 0.0f, 0.0f, 0.0f, 0.6f });

// 画面の隅に貼る
auto& hud = scene.CreateGameObject("Minimap HUD");
auto& sprite = hud.AddComponent<Trident::SpriteRendererComponent>(
    DirectX::XMFLOAT2{ 200.0f, 200.0f });
sprite.SetRenderTexture("minimap");               // カメラと同じ名前
```

UIに出す場合はUI Imageへ`SetRenderTexture("minimap")`を使います
（Rect Transformでアンカー配置できます）。

決まりごと:

- **名前で結びます** — カメラ側の描画先名と表示側の名前が一致すれば繋がります。
  同じテクスチャを複数のSpriteやUI Imageから同時に表示できます。
- **2D／UIはテクスチャへ描かれません** — テクスチャを表示しているSprite自身が
  写り込む無限ループを防ぐためです。映るのは3Dだけです。
- **Bloom・トーンマッピング・FXAAは適用されます**（品質設定に従います）。
- **背景色のアルファを下げると半透明**になります。上のミニマップ例のように
  下地を透かせられます。
- **解像度は小さめが軽い**です。ミニマップなら256x256で十分です。
  1フレームに1回、カメラごとに描き直されます。
- **Scene Viewでも更新されます**（停止中でも絵が出ます）。
- Scene切り替えでテクスチャは破棄され、次のフレームで作り直されます。
- カメラ側の名前を空にすると、通常どおり画面へ描くカメラに戻ります。

## よくあるつまずき

- **ミニマップが真っ黒** — Camera側の描画先名とSprite側の名前が一致しているか、
  そのカメラが有効か（GameObjectごと無効になっていないか）を確認します。
  2D／UIはテクスチャに描かれないため、映すのは3Dオブジェクトだけです。
- **画面が暗い／真っ黒** — シーンにライトがあるか確認します（新規シーンには
  「太陽光」が自動で入りますが、削除すると環境光だけになります）。
- **影が出ない** — ライト側の影設定がONか、品質プリセットがLow
  （影無効）になっていないかを確認します。
- **モデルが表示されない** — 対応形式（.gltf/.glb/.fbx/.cmo等）か、
  ModelRendererへ割り当て済みかを確認します。Inspectorの「描画経路」で
  実際にどの経路で描かれているかも確認できます。
- **映り込みがそれっぽくならない** — プロシージャルSkyboxのままでは簡易的な
  環境光のみです。`.dds`キューブマップを設定するとIBL（粗さに正確な反射）が
  有効になります。
- **遠くの物が急に消える** — LOD Groupの非表示距離、またはカリング設定を
  確認します。「シーン環境 → 描画カリング」でどの段階で除外されたかが
  数字で分かります。
- **パーティクルが眩しすぎる／地味すぎる** — 加算合成（発光向け）と
  通常アルファ合成（煙など）の切り替えとBloomのしきい値を調整します。
